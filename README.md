# 💸 My Budget Spending Streak

A mobile budget tracker for Android and iOS. Log what you spend, stay under
your daily budget, and keep the streak going. Built with
[Capacitor](https://capacitorjs.com) — one HTML/CSS/JS app, two native stores.

> This is the **app** version. The original personal web tracker lives in
> [MyStreak](https://github.com/daniel-shecco/MyStreak) and is unchanged.

## What it does

- **Streak** — consecutive days you stayed within your daily budget, plus your
  best-ever run. A day with nothing logged counts as a day under budget; today
  only breaks the streak once it actually goes over.
- **Month view** — a calendar where each day shows its total, each week shows
  its own total, and days over the daily budget turn red. The whole month view
  turns red when the monthly budget is exceeded.
- **History** — every month since you started, with budget vs. actual and a
  green/red result per month.
- **Private by design** — data is stored on the device only. No account, no
  server, no analytics.

## Develop

```bash
npm install
npm run serve          # http://localhost:5173 — plain browser, no ads
```

Editing anything in `www/` is enough; run `npx cap sync` to push changes into
the native projects.

## Run on a device

```bash
npx cap sync
npx cap open android   # opens Android Studio
npx cap open ios       # opens Xcode (macOS only)
```

**Android** needs [Android Studio](https://developer.android.com/studio) with
an SDK and JDK 21. **iOS** needs a Mac with Xcode and CocoaPods — there is no
way around the Mac requirement for building or submitting an iOS app.

## ⚠️ Before you publish: replace the ad IDs

The app currently uses **Google's public test ad units**, which show fake ads
and earn nothing. That is deliberate — using live ads during development gets
AdMob accounts banned. To go live:

1. Create an app in the [AdMob console](https://admob.google.com) for Android
   and again for iOS (they are separate apps with separate IDs).
2. Create a **banner** ad unit for each.
3. Replace the IDs in these three places:

| What | Where |
| --- | --- |
| Banner unit IDs | `www/app.js` → `AD_UNITS`, and set `USE_TEST_ADS = false` |
| Android app ID | `android/app/src/main/AndroidManifest.xml` → `com.google.android.gms.ads.APPLICATION_ID` |
| iOS app ID | `ios/App/App/Info.plist` → `GADApplicationIdentifier` |

4. Run `npx cap sync`.

Never tap your own live ads — even once. That is the fastest way to get an
AdMob account permanently disabled.

## Publishing checklist

**Both stores**

- [ ] Decide the final app ID. It is currently
      `io.github.danielshecco.budgetstreak` in `capacitor.config.json` —
      **this cannot be changed after the first upload**, so settle it now.
- [ ] Host the privacy policy and have its URL ready. Enable GitHub Pages on
      this repo (Settings → Pages → branch, `/docs` folder) and the policy is
      served at `https://<user>.github.io/my-budget-spending-streak/privacy.html`.
- [ ] Screenshots for the listing (phone sizes; the stores each have their own
      required dimensions).
- [ ] Confirm the consent flow appears on an EEA device before release.

**Google Play** — $25 one-off

- [ ] Create a signing keystore and keep it somewhere safe; losing it means you
      can never update the app again.
- [ ] Build a signed **AAB** (`Build → Generate Signed Bundle` in Android Studio).
- [ ] Fill in the **Data safety** form: declare that the app shows ads and that
      the ad SDK may collect a device identifier and approximate location.
- [ ] Complete the ads declaration and the content rating questionnaire.

**Apple App Store** — $99/year

- [ ] Enrol in the Apple Developer Program.
- [ ] Fill in **App Privacy** ("Data used to track you" → identifiers, because
      of AdMob).
- [ ] Keep the App Tracking Transparency prompt — Apple rejects apps that ask
      for the advertising identifier without it. The wording lives in
      `Info.plist` under `NSUserTrackingUsageDescription`.
- [ ] Archive and upload from Xcode.

### A realistic note on the ads

Banner ads pay in the region of a few euros per *thousand* views. An app with a
handful of users earns approximately nothing; this only becomes real money with
real distribution. Treat the ad setup as plumbing that is ready when an audience
exists, not as income on day one.

### On store review

Both stores reject apps that are just a website in a wrapper (Apple's guideline
4.2, Google's minimum-functionality policy). This app ships native storage, a
native consent flow, launcher icons and a splash screen, which helps — but if
review pushes back, the strongest additions would be a home-screen widget and
local reminder notifications.
